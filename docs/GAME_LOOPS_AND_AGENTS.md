# Play loops and player agents

## The next playable loop

The street currently offers a strong transaction loop: find a space, park, collect, spend coins on a car or building. It needs reasons to move around the city while the parked car earns. Add a **City Passport** with five first-visit goals: park legally on two different roads, visit the cinema, finish a practice race, look at a burger shop, and collect once. Show one goal at a time in a compact street card and all goals on the map. Completing it unlocks a cosmetic color or decal only. Its first implementation can be local to the browser; before awarding tradable or economic value, move the achievement evidence and reward rules on-chain. No paid images or new currency are needed.

| Timescale          | Player choice                                                                               | Feedback                                                               | Next implementation                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1–3 minutes        | Drive to an open curb; choose a legal low-risk space or a higher-risk illegal space.        | Parking animation, visible earnings clock, clear rule and ticket risk. | Show expected gross, meter fee, durability cost and expiry before confirming.                                               |
| 5–15 minutes       | Collect, repair, try the short practice course, stop at cinema or burger site.              | A new car look, personal best time, city passport progress.            | Add a replayable practice course with ghost of the player's own best run; no coin payout in V1.                             |
| Daily              | Compare streets and car builds; decide where to park next.                                  | Map occupancy and a small personal summary.                            | Add a daily three-choice route card based on current open spaces; avoid login penalties or streak loss.                     |
| Owner, across days | Choose building style and media, set parking rule, observe traffic and meter/ticket income. | Seven-day legal/illegal visits, known revenue and ad-view estimates.   | Add a simple rule preview showing expected driver earnings and owner meter income; keep the five-minute rule delay visible. |

Use _variety, mastery and ownership_ for repeat play. Different road layouts and destination art make each drive recognizable; car upgrades improve handling or racing records as well as coin rate; buildings should look distinct at each width and level. Do not add randomized paid rewards, punitive streaks or unlimited uncapped coin bonuses. The first success measure is whether a player voluntarily makes a second drive or destination visit, not time trapped in a screen.

## Economy trial before changing prices

The current 60-coin/hour tier-1 rate and 30-minute cap yield up to 30 coins for a full legal free-curb session before repair costs. The user-visible loop should display this math. The API now records seven-day issued, spent and net coin flow; plot stats separate known owner meter and ticket proceeds. These are **scripted/testnet observations**, not evidence of real player behavior. Run an invited playtest with consented anonymous event counts for: first legal park, first collect, second park, first repair/upgrade, cinema/practice visit, and return on another day. Review the median time to each action, failed parking attempts, 7-day issued/spent ratio, owner revenue concentration, and feedback from five to ten players. Adjust rate, car prices and destination pacing only after that sample. Keep impression estimates separate from coin accounting.

## Headless agent V0

`npm run agent:plan -- --account player.testnet` observes finalized testnet state without a key and prints one action. The policy in `scripts/agent-policy.mjs` parks an owned car in a legal Free curb, waits until its earning cap, collects before expiry, or settles an expired session. It rotates its plot search by account ID to reduce first-space contention. It does not purchase, upgrade, ticket, upload art, move a visible car, or submit ad impressions. `node --test scripts/agent-policy.test.mjs` covers the choice. A read-only plan was checked against a registered testnet player on 2026-11-13; no agent transaction was signed.

The parking-agent pilot now has an owner-facing key setup and a local runner:

1. On the computer that will run the agent, from this repository run `npm run agent:key:new -- --account player.testnet`. It creates `~/.near-estate-agent/player.testnet.key.json` in a private 0700 directory with a 0600 file and prints **only the public key**. The key file must stay on that computer, outside the repository. The command refuses to overwrite it.
2. In **Live city → Parking agent**, connect the same account, paste that public key and choose **Allow or recover parking agent**. The wallet adds a key restricted to this contract and exactly `park`, `collect`, `settle_expired`, with 0.05 testnet NEAR of finite gas allowance. The screen checks the finalized on-chain key; it can recover an existing matching key after browser storage is cleared.
3. Run `npm run agent:run -- --account player.testnet --car-id 1 --key-file /absolute/path/player.testnet.key.json` on that computer, using the car ID shown in Live city. It plans and sends at most one zero-deposit action every five minutes, stops on a failed action or key check, and resumes a pending signed transaction before planning another. It waits if a different car has the active parking session. `npm run agent:plan -- --account player.testnet --car-id 1` remains read-only; `npm run agent:act -- --account player.testnet --car-id 1 --key-file /absolute/path/player.testnet.key.json` sends one action.
4. To stop permanently, use **Revoke parking agent** in Live city while connected with the player wallet. Merely closing the runner or disconnecting the browser wallet does not revoke the on-chain key. If browser storage is lost, paste the existing public key again to recover the controls. Check that the finalized account key list no longer contains it.

The runner checks the key's exact method list, receiver and maximum allowance before signing; a browser gameplay key with broader methods is rejected. The chosen car ID limits the runner's behavior, not the key's protocol permissions: anyone holding the key could call the allowed parking methods for another car on the same account. The gas allowance is a one-time protocol limit, not an internal-coin budget or a daily reset. This first agent cannot spend coins or attach NEAR, so no coin escrow is needed. The agent can stop when its car needs repair; repair remains a player action. The key has no protocol expiry, so owners must revoke it to end access. The signed browser-wallet setup and agent transaction still need an end-to-end testnet journey on a connected wallet.

The public chain remains authoritative. An agent must pay transaction gas from its allowance and obey the same car durability, slot occupancy, earning cap and rule snapshot as a human. It can be front-run or lose a space between observation and execution; the next cycle should refresh state. Keep read RPC requests and action frequency bounded; one action per process run is the current bound. A future scheduler can run every few minutes, but it should respect pending transactions and stop when the key allowance is low. Agent-generated views must never count as ad impressions.

2. Run the invited pacing trial and tune published config only with its measurements. Ship the locally updated owner panel with the next web release and verify its live income and ticket-cap display.

4. Add a separate **plot/building-agent phase**: owner-approved methods for ticketing and rule changes first, then coin-costed repair, car upgrade or building changes. Use a distinct key, per-day coin spending limit and scoped plot IDs enforced by contract methods. A NEAR key allowance controls gas only. Keep plot purchases wallet-confirmed because they require an attached NEAR deposit; artwork still passes the operator's moderation flow.

The proposed [Harbor Horse Course](HORSE_RACING_PLAN.md) adds a free spectator destination first, then a separately reviewed, coin-only house-betting mode. Betting is outside the current headless agent's permissions.

## Plot and building agent: next implementation phase

1. Give the owner a separate agent key and an on-chain grant for selected plot IDs, an expiry, a daily action limit and a daily coin-spending ceiling. The existing NEAR key allowance still caps only gas. Store the small grant under separate keys so the current version-2 root layout stays compatible; charge the owner for bounded new storage through a wallet-confirmed setup call.
2. Add agent-specific contract entry points for `ticket` and `set_rule` first. They must check the signer public key, account owner, selected plot, grant expiry and action count before calling the same internal game logic as the human methods. The new key must **not** allow the original owner methods, which would bypass the grant. Test a rule change taking effect after its normal delay and an illegal ticket respecting cooldown and the existing reward cap.
3. Add coin-costed repair, car upgrade and building change actions only after contract-enforced spending counters are live. Keep the coins in the player's balance and reject a call that would exceed the selected daily ceiling. A design choice that invalidates approved art or media gets its own explicit permission. Plot purchases remain wallet-confirmed because a normal function-call key cannot attach the required NEAR deposit.
4. Permit agents to prepare image prompts or uploads through plot-scoped API authorization, with the same byte validation and moderator review as human submissions. Approval remains with the moderator. Show every agent action, remaining budget and a one-click key revocation path in the owner UI.
5. Rehearse the code-only upgrade against imported live state, then run a signed sandbox and disposable-testnet sequence for over-budget calls, wrong plots, expired grants, revoked keys, competing owner edits and interrupted transactions before inviting players to delegate plots.
