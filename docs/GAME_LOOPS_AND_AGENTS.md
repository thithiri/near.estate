# Play loops and player agents

## The next playable loop

The street currently offers a strong transaction loop: find a space, park, collect, spend coins on a car or building. It needs reasons to move around the city while the parked car earns. Add a **City Passport** with five first-visit goals: park legally on two different roads, visit the cinema, finish a practice race, look at a burger shop, and collect once. Show one goal at a time in a compact street card and all goals on the map. Completing it unlocks a cosmetic color or decal only. Its first implementation can be local to the browser; before awarding tradable or economic value, move the achievement evidence and reward rules on-chain. No paid images or new currency are needed.

| Timescale          | Player choice                                                                               | Feedback                                                               | Next implementation                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1–3 minutes        | Drive to an open curb; choose a legal low-risk space or a higher-risk illegal space.        | Parking animation, visible earnings clock, clear rule and ticket risk. | Show expected gross, meter fee, durability cost and expiry before confirming.                                               |
| 5–15 minutes       | Collect, repair, try the short practice course, stop at cinema or burger site.              | A new car look, personal best time, city passport progress.            | Add a replayable practice course with ghost of the player's own best run; no coin payout in V1.                             |
| Daily              | Compare streets and car builds; decide where to park next.                                  | Map occupancy and a small personal summary.                            | Add a daily three-choice route card based on current open spaces; avoid login penalties or streak loss.                     |
| Owner, across days | Choose building style and media, set parking rule, observe traffic and meter/ticket income. | Seven-day legal/illegal visits, known revenue and ad-view estimates.   | Add a simple rule preview showing expected driver earnings and owner meter income; keep the five-minute rule delay visible. |

Use _variety, mastery and ownership_ for repeat play. Different road layouts and destination art make each drive recognizable; car upgrades improve handling or racing records as well as coin rate; buildings should look distinct at each width and level. Do not add randomized paid rewards, punitive streaks or unlimited uncapped coin bonuses. The first success measure is whether a player voluntarily makes a second drive or destination visit, not time trapped in a screen.

## Economy trial before changing prices

The current 60-coin/hour tier-1 rate and 30-minute cap yield up to 30 coins for a full legal free-curb session before repair costs. The user-visible loop should display this math. The API now records seven-day issued, spent and net coin flow; plot stats separate known owner meter and ticket proceeds. These are **scripted/testnet observations**, not evidence of real player behavior. Run an invited playtest with consented anonymous event counts for: first legal park, first collect, second park, first repair/upgrade, cinema/practice visit, and return on another day. Review the median time to each action, failed parking attempts, 7-day issued/spent ratio, owner revenue concentration, and feedback from five to ten players. Adjust rate, car prices and destination pacing only after that sample. Keep impression estimates separate from coin accounting.

## Headless agent V0

`npm run agent:plan -- --account player.testnet` observes finalized testnet state without a key and prints one action. The policy in `scripts/agent-policy.mjs` parks an owned car in a legal Free curb, waits until its earning cap, collects before expiry, or settles an expired session. It rotates its plot search by account ID to reduce first-space contention. It does not purchase, upgrade, ticket, upload art, move a visible car, or submit ad impressions. `node --test scripts/agent-policy.test.mjs` covers the choice. A read-only plan was checked against a registered testnet player on 2026-11-13; no agent transaction was signed.

For execution, a player must separately provision a **dedicated function-call access key** on their own testnet account, restricted to this exact game contract and only `park`, `collect`, `settle_expired`, with a finite small NEAR allowance. Store `{ "accountId": "player.testnet", "secretKey": "ed25519:..." }` as a regular 0600 file outside the repository, then run `npm run agent:act -- --account player.testnet --key-file /private/path/agent-key.json`. The script checks the live key's receiver, method list and allowance before signing one zero-deposit action. It writes a protected pending signed-transaction journal before broadcast and reuses those bytes on a retry. The account owner can revoke the key on-chain. Do not copy a browser gameplay key or a full-access key into the agent. Key provisioning still needs a dedicated owner-facing flow and a signed end-to-end test.

The public chain remains authoritative. An agent must pay transaction gas from its allowance and obey the same car durability, slot occupancy, earning cap and rule snapshot as a human. It can be front-run or lose a space between observation and execution; the next cycle should refresh state. Keep read RPC requests and action frequency bounded; one action per process run is the current bound. A future scheduler can run every few minutes, but it should respect pending transactions and stop when the key allowance is low. Agent-generated views must never count as ad impressions.

## Next phases

1. Add the City Passport and driving feedback in the client using existing cinema, burger and practice destinations. Test landscape touch layout and the first park-to-collect journey.
2. Run the invited pacing trial and tune published config only with its measurements. Ship the locally updated owner panel with the next web release and verify its live income and ticket-cap display.
3. Add an owner-facing, revocable agent-key creation screen, explicit bot label and a one-action agent preview. Complete a sandbox and testnet signed journey with a dedicated key.
4. Add optional agent policies for choosing a street, returning to a favorite building, or practicing the course. Keep land purchases, content moderation, advertising claims and real-money actions outside agent permissions until each has its own reviewed authorization model.
