# Asset pipeline

1. Owner selects type, level, palette and a description up to 800 characters.
2. API authenticates the wallet session and checks finalized ownership, type, level and revision.
3. Operator budget and quota are reserved before durable job enqueue.
4. Provider adapter generates candidates; decoded raster content is normalized to transparent 560×640 PNG.
5. Validate actual alpha bounds, level envelope, logo/ad rectangles, perspective and content. Hash immutable sprite and thumbnail bytes.
6. Owner previews up to three choices against real neighbours and submits one exact manifest hash.
7. Moderator approves the exact composite and chain revision; clients render only the currently approved hash.

Canonical manifest JSON sorts object keys recursively with no whitespace, UTF-8 encodes, then SHA-256 hashes. `packages/shared/src/assets.ts` implements this rule. A rejected or failed job leaves the prior building live. Provider outputs are not trusted geometry or authority.

Phase 5 now offers a durable **curated mock job**. Each of its three choices has a separately composited 560×640 PNG, thumbnail, validated manifest and SHA-256 hashes. The API saves the owner's description and binds the job to the exact building type, level, layout revision and appearance revision. Only that account can read the private images. The owner screen compares choices beside current chain-read neighbours, then submits one immutable candidate as an on-chain `propose_appearance` call. The service marks it submitted only after the complete pending reference appears on-chain; a selected job can be restored and retried after a wallet redirect. A protected moderator page presents the selected image with current neighbours. Approval or rejection signs the complete pending reference, and the API publishes only the approved selected image after reading the finalized decision. A moderator can later revoke an active design; its immutable asset remains in history while the chain clears its display permission. The live street verifies the approved manifest hash before loading its sprite. If that public sprite fails to load, its curated preset and palette mask replace the gray placeholder while the approved image retries with bounded backoff. Approved media moves to the catalog's matching rectangles during the fallback and back to the manifest rectangles on recovery. Withdrawal selects the preset directly. The description still does not alter the curated images. A real browser-wallet journey and the image provider remain open. No paid image calls have been made for this project.

Logo and billboard uploads are separate immutable PNG records. An owner may prepare a media proposal from an upload with an optional HTTPS destination, then sign `propose_media` with the wallet. The API records submission only after the exact hash, link, owner, building type, level, layout and media revision appear on-chain. The protected review page embeds private proposed bytes, signs exact approval or rejection, and publishes only after the matching finalized decision. It can withdraw an active exact image/link pair later. The street places eligible approved logos and billboards in the facade's catalog or approved-manifest rectangles, loading nearby images lazily. Unapproved or unavailable logos show building initials; billboards remain hidden. The tests use a fake moderator signer; real named-wallet and moderator transactions remain unverified.

The versioned Phase-6 prompt builder is now attached to new mock jobs. It records the five type silhouettes, paid level height, 140×160 logical envelope, 560×640 normalization target, palette, optional theme and two material hints, quoted owner description, and current approved manifest hash as an optional identity reference. Its SHA-256 fingerprint and full text persist in SQLite; an additive migration leaves older jobs with a null prompt. Prompt text remains advisory: decoded art and placement must pass post-generation validation. The UI labels these hints as preparation for prompted art because the current candidate images are still curated. No provider credentials or paid calls are configured.
