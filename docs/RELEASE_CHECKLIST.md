## Final release run

1. Record a source revision and immutable web/API/worker image digests. Run `npm ci`, `npm run check`, `npm run build`, `npm run assets:check`, `npm run contract:test`, and the candidate-specific `npm run testnet:code:plan`. Attach outputs and hosted CI run ID. A code upgrade uses `npm run testnet:code:upgrade` only with the protected deploy key and its prepared recovery record.
2. Run the Phase-4 and Phase-5 browser journeys with **both** MyNearWallet and Meteor on the agreed desktop and phone devices. Record wallet version, device/OS/browser, signed transaction hashes, access-key removal, screenshots of parking and owner approval, and failure recovery. Inspect the current production-dependency audit before signing off the web bundle.
3. With a finite six-call spike budget, test transparent generation and reference edits with the configured dated model. Record response IDs, latency, actual [provider project cost](OPERATIONS.md), output quality, placement, rejection rate and the exact testnet publication transaction. Keep the paid switch off until this evidence and reviewer capacity exist.
4. Deploy the frozen candidate to the target VPS with TLS, persistent SQLite/assets, separate restricted moderator/inspector keys, health checks, log retention, and indexer/budget alerts. Verify from an external network and perform a fresh-volume restore that resumes the event cursor without double counting. Record certificate, alert receiver, backup and restore evidence without secrets.
5. Run a fresh-account driver and owner journey on the deployed testnet game, including another account seeing the approved building and billboard. Check full-curb fallback to a tower/free activity, expiry reuse, repair and upgrade, and operation with image generation disabled. Publish only after all earlier open gates have evidence and record the public URL plus release revision here.

## Known V1 limits to disclose

- Coins are internal, nontransferable game points. Plots and cars are contract registries, not transferable NFT interfaces.
- The inspector account chooses patrol targets; the contract limits each illegal session to one chance and a bounded window. The operator runs impression counting, image hosting and moderation.
- Advertiser impressions are client-reported estimates, deduped and capped by the service; they are not billing-grade proof.
- The street is played in landscape on phones; portrait provides navigation and a rotate prompt. The practice race is solo and its best time is stored in the browser.
- Paid generation is opt-in and disabled by default. Curated facades remain usable during a provider outage. The image provider's final invoice requires separate reconciliation.
- The current production dependency audit reports zero high findings after scoped Meteor dependency patches. Both named wallets still need real signing tests before this bundle can be released.
- Clean-lockfile override trials with patched `query-string` 9.5.1 and 10.0.0 removed those high findings but broke Meteor SDK's ESM import. The current web test suite checks that import; neither incompatible override is in the release tree.
- The compatible `query-string` 7.1.3 path now uses patched `decode-uri-component` 0.5.1 and Meteor's `nanoid` 5.1.16. Two small manifest patches align the declared ranges. Clean `npm ci`, `npm ls`, the full check, guest and live builds, and the zero-high production audit pass. Real Meteor and MyNearWallet signing remains the release gate.
