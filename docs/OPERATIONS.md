The event worker runs as the optional Compose `indexer` profile and shares the API's `/data/estate.sqlite` volume. Back up the shared SQLite volume with the API stopped or through a consistent SQLite backup. The sparse backfill recovered all 80 plot and seven NPC seed events from the current contract in 22 seconds, then normal polling resumed; two fresh worker containers resumed the persistent cursor and the reopened API reported its new height. For a historical gap larger than 100 heights, the worker reads [FastNear Account History](https://docs.fastnear.com/tx/account) for transactions whose receipts reached the contract, resolves their exact receipt logs through [Transactions by Hash](https://docs.fastnear.com/tx/transactions), and checks their block hashes through [Block Range](https://docs.fastnear.com/tx/blocks). It anchors the saved cursor and the new checkpoint to archival RPC, imports only successful contract receipt events, and uses recent finalized-block polling whenever the cursor is within 100 heights of the tip. A 1,000-block transaction overlap covers contract calls whose execution receipt lands after an earlier checkpoint; the V1 contract emits game events in its direct call receipt. The import commits all events, aggregates and the cursor in one SQLite transaction and refuses duplicate receipt identities or a changed anchor. Run it against the same persistent volume as the API, with no other indexer instance writing concurrently. A successful sparse pass now waits 30 seconds before the next pass; repeated provider 429s back off from the provider's Retry-After hint to at most two minutes, and a stop signal interrupts that wait. Watch the indexed timestamp in stats rather than assuming the process is fresh merely because it is running. [FastNear RPC guidance](https://docs.fastnear.com/rpc) documents optional bearer-key authentication for archival requests; sustained hosted indexing may need a protected provider key or more capacity.

The expiry service is defined in `infra/compose.expiry.example.yaml`. It checks all 160 curb and 96 tower spaces against finalized chain time once per minute, then settles up to eight oldest expired sessions per pass by default. The cap can be set to 1–32 with `EXPIRY_MAX_SETTLEMENTS_PER_PASS`; `EXPIRY_SWEEP_INTERVAL_SECONDS` can slow scans to 60–900 seconds if the RPC is rate-limited. A concurrent player collection or space reuse can win the race; after a failed call, the service rechecks that exact session and leaves uncertain still-present sessions for the next pass. The contract's session ID and one-settlement guard prevent a duplicate payout. This sweep pays already-earned coins and frees storage state; it does not decide parking legality or extend earnings. The API container does not receive its key.

Each completed or failed expiry pass writes `/status/sweep.json` atomically to the dedicated `expiry_status` volume. The record includes the contract, completion time, eligible/attempted/settled/raced/failed counts and consecutive failed passes; it preserves the failure count across restarts. When running the monitor with the expiry override, set `ESTATE_MONITOR_EXPIRY_STATUS_FILE=/expiry-status/sweep.json`. The monitor then alerts on a missing, malformed, wrong-contract or stale record and on three consecutive passes with an unresolved settlement or sweep error. Its default stale threshold is 900 seconds; if `EXPIRY_SWEEP_INTERVAL_SECONDS` is raised, set `ESTATE_MONITOR_EXPIRY_MAX_AGE_SECONDS` above the expected pass duration plus interval. The monitor mounts the status volume read-only and never receives the expiry signing key. Local status and alert tests pass; live alert delivery and a hosted expiry pass remain open.

The optional `infra/compose.monitor.example.yaml` starts a separate read-only monitor process. Supply `ESTATE_MONITOR_WEBHOOK_URL` as an operator-controlled HTTPS endpoint, a protected bearer-token file through `ESTATE_MONITOR_TOKEN_HOST_FILE`, and `ESTATE_MONITOR_DAILY_BUDGET_USD_MICROS` as **0 only while paid generation is off**, otherwise the exact API daily budget. Add the monitor override and `--profile monitor` to the production Compose command. The monitor checks the finalized block timestamp every 60 seconds; a cursor more than 900 seconds old, a missing/wrong-contract cursor, or an unavailable database is critical. It warns when reserved plus conservatively charged image spending reaches 80% of the daily ceiling and marks 100% critical. An absent paid-ledger table is critical when budget monitoring is enabled. To monitor inspector patrols, also include the inspector override and set `ESTATE_MONITOR_INSPECTOR_STATUS_FILE=/status/patrol.json`; the monitor mounts that shared status volume read-only. It alerts for a missing, invalid, wrong-contract or more-than-900-second-old record, or three consecutive patrols whose attempted transactions all failed. Set `ESTATE_MONITOR_INSPECTOR_MAX_AGE_SECONDS` only if the patrol interval changes. It sends a small JSON event to the authenticated webhook, retries failed delivery next pass, reminds every 30 minutes, and sends a resolved event after recovery. The endpoint should deduplicate alerts by contract, category, state and time because the monitor resends after a restart. In `--run` mode it also sends a `kind: "heartbeat"` event every 300 seconds by default (configurable with `ESTATE_MONITOR_HEARTBEAT_SECONDS`). An independent receiver must alert when it has seen no heartbeat for 15 minutes and check public HTTPS separately; receiving alert events alone cannot reveal a whole-VPS outage.
