## Release decision

A targeted pre-push check of the current 101-commit history found no tracked environment, database or credential file and no literal PEM, OpenAI project-key or NEAR secret-key pattern. The only `private_key`/`secret_key` matches are source code for protected runtime key files. This does not prove that every possible secret format is absent; review the chosen GitHub destination and access settings before the first push.

This review found no new code change required in the paths inspected. It does **not** close Phase 8: the named-wallet, physical-device, hosted TLS, external restore and operator sign-off gates remain open. Paid-provider evidence remains a gate only for enabling generated art; the curated-only beta keeps that feature disabled. Re-run the review if authentication, storage accounting, moderation or contract serialization changes.

After this snapshot, a [live testnet key-only handover](../deployments/testnet-role-key-handover.json) added and removed overlapping restricted moderator and inspector keys, returning both accounts to one full-access key. The hosted service restart and controlled role action still need separate evidence.

A later [local moderator-container handover](../deployments/testnet-moderator-container-rotation.json) restarted the API with the replacement key and verified its live role and permission. The authenticated status route also detected revocation without marking the whole API unhealthy. No container-signed content decision or VPS restart has been verified.

The moderator revocation race found after this review was fixed in source and verified in local unit/WASM tests. The [code-only testnet release](../deployments/runtime-upgrade-live-ad148df441a41d1f.json) now runs that WASM; its [finalized-block postcheck](../deployments/runtime-upgrade-postcheck-ad148df441a41d1f.json) confirms code, roles and unpaused city state. This is code-identity evidence for the fix, not a live moderator takedown or a renewed full security sign-off.

At source revision `e0987e7`, a fresh production dependency audit again exited successfully with 17 low and zero high findings. The live web build warned about `eval` inside `js-sha256`'s Node-detection branch. A packaged browser reached the Meteor chooser under Caddy without page or console errors, but an explicit `securitypolicyviolation` listener later found Zod's `Function()` probe blocked by the game policy. The game now sets Zod's pinned `jitless` option before module loading; the [packaged follow-up](../deployments/local-packaged-csp-check-2026-11-11.json) reports zero script-policy violations and page errors. This still does not cover a signed wallet action.
