# Focused security review

Snapshot: 2026-11-11, branch `codex/estate-mvp`. This review covers the invite-beta code paths named in V1 task 60. It is a source and local-test review; it is not a hosted penetration test or a signed release approval.

| Surface                    | Evidence reviewed                                                                                                                                      | Result and remaining limit                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Contract roles             | `Contract::new`, `require_admin`, `require_moderator`, inspector method gates; unit and sandbox role tests                                             | Initialization requires a self-call with the contract as admin. Moderator and inspector actions check their role accounts. Current shared-city code and roles have a verified state-preserving deployment. A role-account change still needs a separate migration or compatible upgrade.                                                                                                                           |
| Coin and storage integrity | Checked coin arithmetic, prepaid account/plot reserves, session occupancy and single settlement; contract unit and sandbox tests                       | The tested paths reject overdraw, double settlement, unowned-plot edits and storage overrun. Representative Borsh value fixtures, all persisted enum tags and the known-owner code-upgrade view check guard accidental layout changes. A schema migration and exhaustive composite-state rehearsal remain open.                                                                                                    |
| Browser keys               | `wallet-client.ts` restricted method/allowance checks, exact signed-transaction recovery, disconnect revocation, web tests                             | Gameplay keys are limited to named contract methods and a finite allowance; an uncertain action reuses the same signed bytes. The key lives in browser storage, so script injection or a compromised device could expose it. Meteor signing and revocation on real devices remain unverified. Intear is available only behind a development flag while its browser message handling and real signing are reviewed. |
| Artwork authentication     | One-use NEP-413 challenge, active wallet-key check, HttpOnly/Strict session cookie, exact Origin guard, account/global issuance limits; API tests      | A stolen or revoked wallet key cannot keep authorizing private artwork requests once the API observes its finalized removal. Hosted TLS, browser wallet differences and an external abuse test remain open.                                                                                                                                                                                                        |
| Media ingestion            | Multipart/body and per-owner quotas; `sharp` input-byte, pixel, page, format and output-byte limits; hash verification; private asset reads; API tests | Candidate and upload bytes stay private until approval. The service verifies stored bytes before serving by hash. Previously public image bytes may remain obtainable or cached after on-chain revocation; revocation removes game display permission, not all historical copies. The [incident procedure](INCIDENTS.md#moderation-and-urgent-revocation) covers takedown escalation.                              |
| Moderator actions          | Exact owner/revision/hash checks on chain, API re-read before signing, restricted moderator function-call key, review page; API and contract tests     | A stale approval/rejection cannot apply to a changed plot. Production operation still needs an independent human review, a hosted key-rotation drill and a temporary-key removal check for each testnet journey.                                                                                                                                                                                                   |
| Dependencies               | `npm audit --omit=dev --audit-level=high` on this checkout                                                                                             | Exit 0, with 17 low findings and no high findings after adding the experimental Intear module. Revisit advisories and wallet compatibility before release.                                                                                                                                                                                                                                                         |

## Release decision

This review found no new code change required in the paths inspected. It does **not** close Phase 8: the named-wallet, paid-provider, physical-device, hosted TLS, external restore and operator sign-off gates remain open. Re-run the review if authentication, storage accounting, moderation or contract serialization changes.
