# Decisions and phase evidence

Updated 2026-11-11. This is a chronological record of choices, sources, and unverified gates. Earlier audit counts describe the tree at the time of each check; the latest state is in the release checklist.

The [invite-beta release checklist](RELEASE_CHECKLIST.md) is the current cross-phase sign-off record; it does not itself establish a passed gate.

## Phase 0 — validation in progress

- Scope is [V1_SPEC](V1_SPEC.md): five roads, 80 player plots, 160 curb spaces, three game-owned 32-space towers, five player building types, six car bodies, short capped parking sessions, and prompted facades with review. NPC garage, cinema, burger stop and practice course are civic sites, never purchasable player building types.
- Deliberate changes from the 2008-inspired handoff: 60 instead of 10 coins/hour, 30 minutes instead of 24 hours earning cap, and 2 instead of 5 durability per park. V1 adds a 2-minute expiry grace, one earning session per player, towers, five player building types and four building levels. Plot price starts at 1 testnet NEAR with 2× corners. A car purchase is 150 coins and upgrades cost 200/500. There is no transferable coin or NFT interface.
- NEAR documents that function-call keys are restricted to one receiver, optional method list and optional gas allowance; they cannot attach NEAR. It documents exhaustion and revocation semantics. Wallet funding is therefore required for registration/purchases. [Access keys](https://docs.near.org/protocol/accounts-contracts/access-keys).
- NEAR Connect currently lists Meteor among supported wallets and documents sign-in and transactions, but the available page does not prove the required MyNearWallet/restricted-key combination. Keep Wallet Selector as a fallback until the two-wallet spike is executed. [NEAR Connect](https://docs.near.org/tools/near-connect).
- The [NEAR indexer guide](https://docs.near.org/data-infrastructure/indexers) recommends Neardata for hosted block documents. The [current Neardata reference](https://docs.fastnear.com/neardata) describes recent finalized blocks with receipt execution outcomes; the [FastNear RPC reference](https://docs.fastnear.com/rpc) identifies a separate testnet archival endpoint for older blocks. A live contract event probe below verified receipt-level replay through both surfaces. The durable indexer remains Phase 7 work.
- PixiJS 8 documents async `Application.init()` and `app.canvas`; use that API. [PixiJS Application](https://pixijs.com/8.x/guides/components/application). Registry versions observed 2026-11-10: PixiJS 8.22.0, Vite 8.3.7, Hono 4.13.17, Zod 4.6.7, near-sdk 5.30.1. Exact versions are pinned in manifests/locks after builds.
- Hono's Node adapter documents `serve({ fetch: app.fetch, port })`; the API scaffold uses that entry point. [Hono Node guide](https://hono.dev/docs/getting-started/nodejs).
- Reference CSS viewports: phone 844×390 landscape, 390×844 portrait; compact checks 667×375 and 320×568; desktop 1366×768 and 1440×900. Actual device models and performance measurements remain open.
- Proposed initial movement for mock play: 100 logical px/second base speed, 180 px/second tier-3 ceiling, 2× acceleration to full speed per second. These are provisional pending playtest.
- Paid image spike has **not run**. Before it does, set a finite spend ceiling and a maximum of six calls; record accessible model/version, latency and actual cost. Provider credentials and spending authorization are not present in this workspace. Generated samples and all four level-envelope checks remain open.
- The disposable testnet contract and accounts are now configured. A direct testnet signer check proved restricted-key permissions, allowance exhaustion and revocation; MyNearWallet/Meteor login, wallet-driven key addition and popup-free browser signing remain open.

## Phase 1 — underway

- npm workspaces plus one Rust workspace keep shared types and contract code in one repository. `packages/shared` validates string coin amounts, world/space records, game defaults, seed geometry and asset manifest envelopes. `contracts/estate/seed.json` has five roads, 80 player plots and seven civic destinations, including 96 tower spaces.
- A single contract will own plots, cars and parking. Internal lookups avoid cross-contract ownership checks on every action. Events use NEP-297 JSON with `near_estate` as the standard; this does not claim NEP-171 NFT compatibility.
- App/web, API and worker share one schema package. Runtime image and data services are self-hosted on a VPS except for the external image inference provider and NEAR block data source.
- Current evidence: Rust unit tests pass and the contract checks for wasm32; TypeScript packages and Vite production bundle build; shared and guest-mock tests pass; seed validation finds 5 roads, 80 plots and 7 NPC sites; API `/health` and `/city` respond locally. Browser checks at 844×390, 667×375 and 320×568 found phone controls or the portrait prompt visible without vertical overflow. CI configuration exists but no hosted CI run has occurred.
- The development Compose file parses locally. Both API and web images built successfully with Docker 28.0.1. An isolated `estate-smoke` Compose run brought the API to healthy state, returned `/health`, `/config` and `/city` (five roads, 80 plots, seven NPC sites), and served the game page through Caddy on port 8080; the containers were then removed. This is local image and runtime evidence, not a VPS deployment or hosted CI run.
- `npm run config:check` compares the Rust `GameConfig::default()` JSON with the shared TypeScript defaults, requiring the same field set and values after snake-to-camel conversion. All 34 contract defaults match. `maxEarningCars` is fixed at one in the shared schema and contract logic rather than a Rust config field. The check now runs in the contract CI job after both Node and Rust setup. It proves default parity; bounds still rely on the respective validators and contract tests.
- The static web image originally omitted `VITE_ESTATE_CONTRACT_ID`, so a Compose deployment could only show the guest preview even after testnet deployment. The web Dockerfile now accepts the value at build time and Compose forwards it. A configured image built successfully, and its bundled assets contain the verified testnet contract ID. This checks bundle configuration, not wallet interactions in the container.
- Every current numeric config field has an explicit shared-schema bound. Contract config validation mirrors those bounds for its current fields; the eventual contract will enforce the same economic snapshots that `packages/shared` already models. The guest mock now snapshots terms, caps earnings, clears expired sessions and limits tickets to a local sample owner.
- Registration quotes 4,096 storage bytes for up to three cars and one parking session; plot purchase quotes a separate 4,096-byte reserve plus the plot price. The earlier 2,048-byte plot reserve failed a unit test with two valid maximum-length logo/billboard records. The new reserve passes both a unit test and sandbox journey with both slots, 256-character links, 500-character decisions, a pending facade and rule; the sandbox plot reports 3,493 bytes used out of 4,096 reserved. Excess attached deposit above the quote is refunded; the quoted reserve is held by the contract for V1 storage and has no withdrawal path. Repeated parking unit tests confirm that completed sessions release their measured storage usage.
- The contract implements one-time prepaid registration, starter car and coins, car purchases with a three-car cap, repair, tier upgrades, emergency repair, and the burger cosmetic. Plot and NPC registries accept paid, idempotent admin seed calls. NPC towers are separate game-owned sites, never player plots; each has exactly 32 spaces at half the curb earning rate.
- The on-chain parking loop now snapshots effective rule and economic terms at park time, supports curb and tower sessions, pays legal meter proceeds, caps earnings, frees expired spaces, and enforces one earning car per player. Owner tickets have a per-plot cooldown; inspector attempts have an age gate, one chance per session and a global rate limit. The inspector's winning share enters the treasury balance. The operator still chooses which eligible sessions to inspect; patrol selection and the resulting treasury income are trusted operator behavior.
- Public session JSON uses `location_id` plus `facility` so curb plots and NPC tower sites cannot be confused. Settlement events use the same fields. Shared event names include the new seed and inspection events.
- Owner plot methods now support two preset variants, the four curated colours, a bounded name, paid type changes, and levels 1–4. Type changes preserve paid level. Choosing a preset, changing type, or upgrading clears the active custom facade and any pending proposal; the last facade publication time survives. Every upgrade grants one same-level publication cooldown exemption, consumed only when an approval needs it. A moderator must match the complete pending owner/type/level/hash/revision tuple; rejection and revocation leave or restore the valid preset. The hash records operator-reviewed asset identity, not a claim that on-chain code validated image pixels.

## Phase 4 — testnet deployment and chain wiring

- The pinned [near-workspaces 0.24.0 API](https://docs.rs/near-workspaces/0.24.0/near_workspaces/) and local source provide testnet workers, credential-file accounts, code/state queries, deployment and contract calls. Code queries on a new account fail instead of returning empty bytes, so the deployment tool checks `AccountDetails.contract_state` before deciding whether to deploy. Its first sandbox run exposed this distinction; the corrected full-city sandbox run passed.
- `npm run deploy:plan` rebuilds the release WASM, runs the shared seed validator and reports the SHA-256 plus 80-plot/seven-site plan without contacting testnet. `npm run deploy:testnet` requires three distinct existing accounts and a full-access credential file outside the repository. It refuses a different on-chain code hash or conflicting seed, verifies roles/config/city after writes, and publishes only public account IDs, versions, counts and code hash in `deployments/testnet.json` after success. The sandbox test deploys to a fresh account, seeds all 80 plots and seven sites, then reruns the same seed and observes zero additions. The same build was deployed to a disposable testnet account and all 80 plots and seven sites were seeded and verified; public IDs and hash are in `deployments/testnet.json`. Browser-wallet transactions remain open.
- The first chain read adapter uses the [NEAR contract view RPC](https://docs.near.org/api/rpc/contracts) with JSON arguments encoded as base64 and `final` reads. It pins a player's car/session reads to the account view's returned block hash so one player snapshot comes from one block. A new `get_street_side` contract view returns a side's eight plots and curb slots in one call, avoiding 16 separate slot reads per refresh. Shared schemas validate the JSON fields consumed by the client, including decimal-string balances and street occupancy. Mocked RPC tests cover a valid player, malformed balances, RPC failure, an inconsistent car owner and misordered street data. The contract's full sandbox journey confirms occupied and released slot data in the new street view. The adapter is mounted in Live city and the illustrated street testnet mode; a browser read against the deployed contract rendered the actual seeded facades and empty curb occupancy.
- Current [Wallet Selector v10 documentation](https://github.com/near/wallet-selector/blob/main/packages/core/README.md) and the [v10 migration guide](https://github.com/near/wallet-selector/blob/main/MIGRATION-v10.md) verify MyNearWallet/Meteor modules, an optional contract/method-limited sign-in key, and bigint-based v10 actions. The documented `createAccessKeyFor` option does not expose a finite gas allowance, so V1 creates a separate function-call key through a wallet-signed `AddKey`, restricted to eight gameplay methods and 0.25 testnet NEAR of gas. The client scopes the key to account and contract, checks the on-chain permission before use, stores redirect-pending operations in session storage, serializes gameplay calls, and offers a wallet-signed `DeleteKey`. These are implementation choices, not live-wallet proof. The pinned selector packages are 10.1.4 and near-js packages 2.3.0. `npm audit --omit=dev` currently reports five high and 14 low transitive findings, with high findings primarily in Meteor SDK's `nanoid` and `query-string` chain. The apparent automatic fix downgrades the Meteor module to selector v9, so it was not applied. Resolve or explicitly accept this before beta.
- The client has a separate Live city screen behind `VITE_ESTATE_CONTRACT_ID`; it reads the selected road side from final-block RPC snapshots and exposes registration, capped-key setup/revoke, purchase, repair, upgrade, curb/tower parking, collection and owner ticket actions. The illustrated Street now has an explicit testnet mode and retains guest mode as a separate local preview. An undeployed sample testnet ID produced the expected missing-contract message in a browser smoke check; no browser wallet was connected or signed. The tower's `get_tower_open_space` view returns its first empty or expired space, so one click does not fan out to 32 RPC reads. Rust tests cover empty, occupied, full and expired tower states.
- The wallet libraries require browser `Buffer` and `global` shims. `vite-plugin-node-polyfills` 0.28.0 is pinned at the monorepo root because Vite 8 resolves the hoisted dependencies there; a workspace-local plugin did not resolve its shim. The [plugin README](https://github.com/davidmyersdev/vite-plugin-node-polyfills) documents the configuration, and the [0.28.0 release](https://github.com/davidmyersdev/vite-plugin-node-polyfills/releases/tag/v0.28.0) records Vite 8 support. The configured browser route and production build load, but the lazy wallet chunk is 1.46 MB before gzip and needs size reduction before a mobile beta. The [NEAR contract-view RPC](https://docs.near.org/api/rpc/contracts) reports missing code inside `result.error`; the reader now surfaces that case and binds `fetch` to `globalThis` to avoid the browser's illegal-invocation error. A browser check confirmed the missing-contract message disables Connect for an undeployed sample ID. The pinned `@near-js/accounts` 2.3.0 source reads the access-key nonce and a recent block before each signed call, and throws on final execution failure by default; the client serializes calls around this SDK behavior.

- The street testnet mode consumes final-block plot, car and session snapshots without copying them into the mock.
