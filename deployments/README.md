# Testnet deployment

The [role-key handover record](testnet-role-key-handover.json) documents a live key-only rotation on the shared city's moderator and inspector accounts. It records two restricted keys overlapping on each account, removal of the old key while the replacement remained valid, removal of the replacement, and the final one-key-per-account state. No contract role action or hosted service restart was part of that drill.

The [local moderation mount probe](local-moderation-mount-probe.json) records a nonroot API container starting with a mode-0600 throwaway key mount, then serving the protected review page. That key had no on-chain permission and the probe was not a signing test.

The [inspector container patrol record](testnet-inspector-container-patrol.json) covers a local one-shot service pass with a real inspect-only testnet key, a healthy heartbeat, final key cleanup and the bounded finality-read fix it exposed. The selected street side had no illegal car, so the container sent no inspection transaction.

The [moderator container rotation record](testnet-moderator-container-rotation.json) covers a local API restart between two live restricted keys, a finalized role/key check before and after old-key removal, and the authenticated status route's response after revocation. Both temporary keys were removed. No moderation decision was submitted by that container.

The current disposable testnet deployment is recorded in [testnet.json](testnet.json), its [tower-floor code upgrade](testnet-floor-upgrade.json), [live floor-3 journey](testnet-tower-floor-journey.json) and [indexed receipts](testnet-tower-floor-indexed.json), the separate two-account chain check in [testnet-journey.json](testnet-journey.json), the restricted gameplay-key check in [testnet-gameplay-key.json](testnet-gameplay-key.json), the [inspect-only patrol journey](testnet-inspector-journey.json) and its [indexed receipt](testnet-inspector-indexed.json), and the finalized event-source check in [testnet-event-source.json](testnet-event-source.json). These files contain public IDs and results only. The [seed indexer backfill](testnet-indexer-backfill.json) recovered 80 plot and seven NPC events from the current contract. The [journey indexer backfill](testnet-indexer-journey.json) recovered real player parking and settlement events and verified plot/economy API totals, replay and rebuild. A [local backup and restore drill](testnet-backup-restore-drill.json) preserved the indexed floor-3 snapshot and a separate uploaded-image fixture. The [initialization-guard rehearsal](testnet-init-guard-plan.json) verified the candidate in a sandbox, and the later [verified upgrade](testnet-code-upgrade-007f67a531c87671f57a96660b4a61f3b7fca6a60681944c5b8227eaf0549c59.json) deployed it with unchanged contract state. Browser wallet signing and a production VPS recovery remain unverified.

Run `npm run deploy:plan` first. It checks the 80 player plots, seven game-owned sites, and release WASM hash without using a wallet or sending transactions.

To deploy, prepare three distinct existing `.testnet` accounts: one contract/admin account, one moderator account, and one inspector account. Keep the contract account's **full-access** credential JSON outside this repository. Set these environment variables in the deployment shell:

For a disposable development deployment, set `ESTATE_DEV_KEY_DIR` to a private absolute directory outside this repository and run `cargo run --manifest-path contracts/estate/Cargo.toml --example bootstrap_testnet -- --apply`. It creates or reuses private credential files for contract, moderator, inspector, driver and owner accounts. Add `--role driver` (or another role name) to create only one account. The script checks that the RPC reports testnet. Never copy those keys into this repository.

To repeat the direct web-client signing journey with a disposable driver on the deployed city, set `ESTATE_DRIVER_KEY_FILE` to that driver's private credential JSON outside this repository and run `npm run testnet:web-signer:journey`. The command registers a starter car if needed, adds a restricted gameplay key, parks and collects on a free curb, revokes the key, and verifies the final on-chain state. It simulates a lost RPC reply after the real parking transaction finalizes, reopens the client and checks recovery without rebroadcast. It keeps its interruption-recovery storage beside the credential file with private permissions and writes only public transaction evidence to [testnet-web-signer-journey.json](testnet-web-signer-journey.json). This exercises the client's direct signer through a local wallet adapter; MyNearWallet and Meteor browser approval remain separate release checks.

| Variable                 | Value                                                   |
| ------------------------ | ------------------------------------------------------- |
| `ESTATE_CONTRACT_ID`     | Existing contract/admin account, ending in `.testnet`   |
| `ESTATE_MODERATOR_ID`    | Existing moderator account ID                           |
| `ESTATE_INSPECTOR_ID`    | Existing inspector account ID                           |
| `ESTATE_DEPLOY_KEY_FILE` | Absolute path to the contract account's credential JSON |
| `ESTATE_TESTNET_RPC_URL` | Optional HTTPS testnet RPC; defaults to FastNear        |

Then run `npm run deploy:testnet`. The command rebuilds the WASM and validates the seed before making a testnet connection. It checks the key's account ID and all role accounts, deploys only if the contract account has no code, initializes only if it has no state, and refuses to overwrite a different code hash. It checks every existing plot and NPC site before adding missing records. The admin attaches one testnet NEAR to each new seed transaction; the contract refunds the amount above measured storage cost. Keep enough testnet NEAR in the contract account for deployment, storage, and gas.

On success, the tool rereads all 80 plots, seven sites, roles, config version, and deployed code. It then writes `deployments/testnet.json` with **public** account IDs, WASM hash, and version/count checks. Rerunning the same build and seed skips matching records. A changed contract binary requires a separate upgrade procedure; this seed command does not replace live code.

The earlier tower-floor view upgrade imported the current city state into a local sandbox, deployed its candidate binary there, and compared every key/value state hash before applying it to testnet. Its verified public record is [testnet-floor-upgrade.json](testnet-floor-upgrade.json); that historical record is never reused by the current upgrade command.

For a new **state-preserving code** release, run `npm run testnet:code:plan`. It verifies the live manifest, roles, counts and tower views, imports the exact current city into a local sandbox, deploys the new binary there, and compares every state key/value, tower view, the new eight-space tower-floor batch and all 80 plot entries in the ten street-side views. It then redeploys the original binary in that sandbox and verifies its code hash, complete state hash, tower views, roles and city counts again. To apply the rehearsed binary, set `ESTATE_DEPLOY_KEY_FILE` to the private full-access credential for the contract account and run `npm run testnet:code:upgrade`. The command saves the old WASM beside that private key, writes a public prepared record named `testnet-code-upgrade-<new-wasm-sha256>.json`, deploys the new code, verifies finalized code, roles, counts, tower views and unchanged state, and then updates `testnet.json`. A matching prepared record can be resumed after an interruption. If post-deploy verification fails, the record first becomes `recovery_required`; it becomes `rolled_back` only after old code, state, tower views, roles and counts are verified. Inspect any `recovery_required` record before retrying. Keep the private old-WASM backup until a later release and backup supersede it. This path does not migrate serialized contract state. The initialization-guard binary was deployed in transaction `GVygPRNfPv1pF4jeUvyFjH6GkksTgNPPgZ67Xjdnp8di`; the verified record shows the same state hash before and after.

`ESTATE_DEV_KEY_DIR=/absolute/private/path npm run testnet:tower-floor:journey` uses the disposable driver on the seeded testnet city. It registers that driver if needed, parks in floor-3 space 16, checks the floor count falls from 8 to 7, collects earnings, and checks that it returns to 8. It writes [testnet-tower-floor-journey.json](testnet-tower-floor-journey.json) with public transaction hashes and payouts. It expects the tower to be otherwise empty; other players occupying that tower would require a different test site.

The worker backfilled that same city from its creation height into a fresh SQLite file, recovered the journey's park and collect receipts, resumed in a second process with zero added events, and rebuilt economy totals from raw receipts. Set `API_DATA_DIR` to that worker database and run `npm run testnet:tower-floor:indexed` to verify the exact session, capacity-independent payout, daily tower totals and absence of NPC activity in player-plot statistics. The check writes [testnet-tower-floor-indexed.json](testnet-tower-floor-indexed.json) with public receipt IDs and block heights. The local verification database is disposable; production worker restart and sustained traffic remain unverified.

For the web client, set `VITE_ESTATE_CONTRACT_ID` to the verified contract ID from `deployments/testnet.json` and rebuild Vite or the Compose web image. Compose passes this variable as a web build argument; changing it without rebuilding leaves the previous static bundle in place. The separate **Live city** screen then reads chain state and offers wallet actions. The illustrated Street also has an explicit testnet mode. Before treating wallet play as complete, run registration and the restricted gameplay-key flow through both MyNearWallet and Meteor. `deployments/testnet.json` is a verification record, not proof that browser wallet play or the indexer works.

`ESTATE_DEV_KEY_DIR=/absolute/private/path npm run testnet:journey` deploys a separate disposable contract with short test timers and runs the meter, ticket, contested-slot, expiry and signer-reconnect checks. It does not change the main city configuration. The main city was seeded after an initial NEAR.org RPC rate-limit failure; the deployment command safely resumed against FastNear without replacing the matching code. The [NEAR RPC provider list](https://docs.near.org/api/rpc/providers) identifies the public testnet endpoints. Public RPC availability and limits can change; use `ESTATE_TESTNET_RPC_URL` for a different verified provider.

After the journey, `ESTATE_DEV_KEY_DIR=/absolute/private/path npm run testnet:gameplay-key` uses its disposable owner account and contract. It creates a short-lived function-call key for the same eight methods as the web client, proves an allowed zero-deposit call, rejects a purchase method, deposit and wrong receiver, spends the small test allowance until the protocol rejects another call, then revokes the key and verifies its absence. It keeps a public-key recovery record in the private directory while running so a later run can remove a key left by an interrupted check. The test allowance is 0.062 testnet NEAR; the web client uses 0.25 testnet NEAR. This is protocol and SDK evidence, not proof of wallet modal or redirect behavior.

`ESTATE_DEV_KEY_DIR=/absolute/private/path npm run testnet:inspector-journey` uses the same disposable contract and dedicated inspector account. It verifies an inspect-only function-call key, temporarily sets deterministic inspector test settings, parks an illegal car, and runs the API patrol against that street. It checks that the session clears, restores the complete prior config except its monotonic version, revokes the key, and deletes the temporary private credential. An interrupted run leaves a public recovery record beside the private key so the next run can settle an expired test session, restore the prior config and revoke the key. This exercise does not configure the production inspector container or its random schedule.

For a dedicated moderation service, `npm run moderator:key:plan` and `npm run moderator:key:apply` provision a separate method-restricted runtime key on the existing moderator account. Set `ESTATE_CONTRACT_ID`, `ESTATE_MODERATOR_ADMIN_KEY_FILE` and `ESTATE_MODERATOR_RUNTIME_KEY_FILE` to the deployed contract and protected absolute key paths outside this repository. The runtime file is the only key mounted through `MODERATOR_KEY_HOST_FILE`; keep the full-access account credential on the operator host. `npm run moderator:key:revoke` removes the restricted key and runtime file during rotation. The API rejects a full-access or wrong-scope key before signing. No production moderator key has been provisioned by this script yet.

`npm run testnet:moderation-journey` creates a separate disposable testnet contract, owner and moderator, proposes a synthetic logo hash, approves and revokes it through a six-method restricted key, then removes that key. By default it uses the public faucet. If that is rate limited, set `ESTATE_TESTNET_SPONSOR_KEY_FILE` to a private full-access credential for an operator-owned account. The alternate route reads the finalized protocol's storage price and release WASM size before creating any account. It funds the contract with at least 10 testnet NEAR or the calculated code deposit plus 1 NEAR, whichever is greater, and funds moderator, owner and inspector with 1, 3 and 0.1 NEAR. The sponsor must have at least the combined amount plus 0.9 NEAR reserve (15 NEAR for the current build). It must be separate from the deployed city's contract, moderator and inspector accounts; the command checks this before creating anything. The sponsor key must be outside this repository with no group or world read permission; it is never mounted in a game service. Each new subaccount's random recovery key is written to a protected temporary directory before its account-creation transaction. The command writes public transaction evidence to [testnet-moderation-journey.json](testnet-moderation-journey.json) only after the full journey succeeds. Faucet-funded recovery credentials are removed on success. Sponsor-funded keys are retained after success so the operator can reclaim remaining testnet balances; all keys are retained after a partial failure. Four faucet attempts on 2026-11-11 stopped at HTTP 429 before account creation. A later sponsored run exposed an underfunded 3-NEAR contract account before moderation actions; that disposable account was deleted and its balance returned. After raising the contract funding to 10 NEAR, the sponsored approval/revocation journey passed on 2026-11-11. The matching sandbox integration test passes, but image upload and human visual review are separate checks.

The follow-up `npm run testnet:media-api:prepare` and `npm run testnet:media-api:approve` exercise actual logo bytes through the local API against that isolated contract. Set `ESTATE_MEDIA_DATA_DIR` to a private absolute directory outside this repository, `ESTATE_MEDIA_CONTRACT_KEY_FILE` and `ESTATE_MEDIA_OWNER_KEY_FILE` to the matching protected account credentials, and `ESTATE_MODERATOR_RUNTIME_KEY_FILE` to a restricted key provisioned with `npm run moderator:key:apply` for that contract. The prepare command seeds and buys a second plot, signs the owner API challenge, uploads a generated PNG, sends the exact proposal and saves the combined facade preview under the private data directory. Inspect that preview before running approve. Approve checks on-chain activation and an anonymous hash-verified asset read, leaving the logo active; then revoke the temporary runtime key with `npm run moderator:key:revoke`. [The 2026-11-11 record](testnet-media-api-journey.json) also verifies the approval event. These commands use in-process Hono routes with real testnet RPC and a local full-access key adapter; browser wallets, a hosted API and independent human review are separate release checks.

With the same isolated contract and protected contract/owner key files, `npm run testnet:owner:journey` exercises the web client's rule and building controls on the other owned plot. It adds and revokes a restricted gameplay key for `set_rule`, selects a curated preset, changes building type and upgrades one level. Because the disposable owner starts with 100 coins, the script briefly lowers only that isolated contract's type/first-level build prices to one coin and restores the original configuration in a `finally` block. It checks the final plot, coin debit, restored prices and key removal, and writes only public hashes to [testnet-owner-customization.json](testnet-owner-customization.json). This checks action wiring, not default-price earning time or named-wallet browser behavior.

`npm run testnet:mock-facade:prepare` and `npm run testnet:mock-facade:approve` continue that isolated owner plot through the curated facade flow. Set `ESTATE_MEDIA_DATA_DIR` to the same private API directory, `ESTATE_MEDIA_OWNER_KEY_FILE` to the protected owner key, and `ESTATE_MODERATOR_RUNTIME_KEY_FILE` to a six-method restricted moderator key provisioned for this contract. Prepare signs an owner API session, makes three private candidates, selects design 2, submits its exact manifest hash on-chain, and writes a moderator preview in the private data directory. Inspect the preview before approve. Approve checks the exact pending revision, publishes it through the API moderator route, verifies the final chain hash and an anonymous manifest and sprite read, and writes [public evidence](testnet-mock-facade-journey.json). Revoke the temporary runtime key afterward with `npm run moderator:key:revoke`. The recorded run resumed a proposal already confirmed on-chain after the first prepare attempt reached the moderator page without a configured key; the proposal transaction hash was not retained, but the exact pending and final chain revisions were verified. This used a local API and disposable key adapter, not the named-wallet browser, hosted service, or independent human moderator.

`ESTATE_DEV_KEY_DIR=/absolute/private/path npm run testnet:event-source` emits one harmless rule event on the separate journey contract and verifies its receipt ID, successful executor and log in a finalized Neardata block. It then checks the same transaction and log on testnet archival RPC, discovers the transaction by scanning its archived inclusion block and chunks, and confirms an older archived block is readable. `ESTATE_FASTNEAR_API_KEY` is optional for this probe and is sent only in request headers if set. The public evidence record contains hashes and logs, never credentials. The later indexer backfills verify the durable history and replay path for the seed city and one player journey; sustained throughput remains open.
